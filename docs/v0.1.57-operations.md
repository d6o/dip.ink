# v0.1.57 operation and review checklist

## Healthcheck and alert state

The existing notification algorithm remains: fire on a changed fingerprint, remind after `NOTIFY_REPEAT_HOURS` (default 12), and send one recovery message. Failed deliveries do not advance state. Jobs still report failures even when notification delivery fails or state is unavailable.

State now selects `NEO4J_DATABASE` explicitly and keys records by job name, `GROUP_ID`, and `NOTIFY_INSTANCE`. An owned connection closes even when the state read fails. Invalid reminder intervals use the 12-hour default with a warning. Compose now passes reminder configuration to both alert jobs.

Legacy unscoped alert records remain untouched. They are not silently assigned to an arbitrary group or instance. Expect one initial firing notification for an existing active alert after this scope change. If continuity of an old recovery message is required, Session A must verify ownership and migrate that record explicitly before rollout. Do not clear all alert state.

The server status graph component exposes its non-secret group/database scope. Healthcheck compares that scope before querying episode presence. A mismatch is a configuration failure, not a claim that notes are absent. Missing scope metadata also fails the check. This requires the matching server version during rollout.

Public configuration remains `GROUP_ID=main`, `NEO4J_DATABASE=neo4j`. Private deployments supply their own values. The server, ingest, and healthcheck must agree. Kubernetes and Compose contracts reject omitted or conflicting group configuration. They also protect the shared database and notification settings where applicable.

## Janitor: manual-only

Kubernetes keeps `contradiction-janitor` suspended. Compose puts it behind the `manual` profile with no restart or internal schedule. The module defaults to `DRY_RUN=1`.

```sh
# Explicit manual report; never add this to a scheduler.
docker compose --profile manual run --rm contradiction-janitor
```

The existing LLM request now uses Graphiti Message objects and schema validation. Provider/schema errors fail visibly instead of returning an empty finding. Console reports contain IDs and counts, not fact bodies. Queries are group-scoped. A write run additionally requires `JANITOR_ALLOW_WRITES=1`; do not enable it without source review and explicit approval. Ambiguous contradictions remain human decisions. This release adds no production LLM judge.

## Zero-edge inspection

Use the existing database environment in an authorized read-only context:

```sh
python /app/loops/zero_edge_report.py --limit 20
# Optional, more expensive provenance-link counts, still read-only:
python /app/loops/zero_edge_report.py --limit 5 --verify-links
```

The first report reads UUIDs, slugs, completion markers, timestamps, and edge-metadata presence only. It distinguishes missing metadata from a completed record with an empty edge list. Verification counts relationships that cite each sampled episode. Zero linked edges is not proof that extraction failed: a note can validly yield zero facts. No report forces reingest or changes completion metadata.

Human inspection of private source evidence is a separate coordinator task. Keep private bodies out of public reports. The report is bounded and does not prove corpus-wide absence or quality.

## Evaluation and queue audit

Use the [evaluation guide](eval/README.md) for 30 synthetic cases and private live captures. Confidence, literal claim hits, and citation membership are not correctness measures. Include abstentions, errors, and missing receipts in denominators. Human reviews bind to the exact dataset hash and run ID.

Use the [reference and queue audit](v0.1.57-reference-audit.md) for read-only blocked/source comparison. Only the dedicated curator may change private queues. Eleven blocked notes or 41 review bullets are counts, not duplicate or obsolescence verdicts.

## Rollout, verification, and rollback

Session A owns publication and deployment:

1. Confirm the intended group/database on the live server, ingest, and healthcheck.
2. Inspect legacy notification-state ownership; preserve its history.
3. Suspend the private janitor and remove any old Compose janitor process explicitly. A profile change alone does not stop an already-running old container.
4. Deploy the reviewed immutable image and matching configuration.
5. Run healthcheck and inspect configuration failures separately from missing-note claims.
6. Confirm firing, reminder, recovery, and failed-delivery behavior with safe fixtures or an approved notification test.
7. Run metadata-first zero-edge inspection and retain private evidence for human review.
8. Run the fixed private evaluation and blocked-note audit without source mutation.

Rollback restores the previous image/configuration but keeps janitor suspended. Preserve scoped and legacy alert records, ingest failure state, source history, and queues. The unresolved items in the [plan](v0.1.57-plan.md) need live evidence; this implementation alone does not resolve them.
